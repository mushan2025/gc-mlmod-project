# 胃癌 MLMOD 项目全局约定（Conventions）

本文件是所有方法学约定的唯一来源。CLAUDE.md 和 AGENTS.md 均引用本文件，不重复其内容。
约定可被推翻——如果有充分理由认为某条约定不利于研究质量，应提出并由用户裁决。

## 0. 核心原则

本项目唯一目标是形成高质量、可执行、可审计、不过度声称的研究方案和分析结果。用户、Codex、Claude Code 和任何其他 agent 的意见都只能作为 reasoning 或执行记录，不能直接作为论文证据。

关键结论必须至少追溯到以下三类真实证据之一：

1. 实际数据文件和输出结果表，例如表达矩阵、metadata、模型结果、source data。
2. 实际运行代码、脚本、命令日志、参数文件和软件版本。
3. 可核验的文献、数据库、官方文档或公共资源。

如果 agent 意见与真实证据冲突，以真实证据为准。若证据不足，结论必须降级为探索性、方向性或不可评价。

### 算法和参数适配原则

任何算法、统计检验、阈值或软件默认参数都不能只因为“常用”“文献用过”或“工具默认”而直接进入主分析。每个正式方法在执行前必须能追溯到三层依据：

1. **工具使用规范**：输入数据类型、表达单位、矩阵方向、基因ID、最小样本/细胞要求、版本接口和关键参数符合该工具或统计模型的适用范围。
2. **项目数据要求**：与F0或对应F节专项审计确认的数据结构一致，例如raw integer counts、RSEM expected counts、processed microarray expression、normalized single-cell data layer、sample-level clinical endpoints等不得混用。
3. **研究问题适配**：该方法确实回答本研究的问题，且不会主动消除目标生物学差异、制造循环定义、伪重复、p-hacking或超出解释边界的结论。

每个F节或gate的method decision应记录：输入层/表达单位、独立统计单位、主方法、关键参数、禁用场景、失败或不适配时的fallback、需要用户批准的变更、以及结果最多允许支持的结论强度。若正式审计发现数据结构不满足预设方法，必须暂停并提交方法变更说明，不得为了跑通而静默换算法、四舍五入数据、改阈值或删样本。

## 1. 阶段边界

### 1a 阶段：主线方案讨论与审核

1a 阶段以自然语言方案为主。此阶段允许反复讨论、反驳、重写和调整，不强制每个小节立即维护结构化 contract 模板。必要时可在自然语言中加入表格、字段清单和 gate 条件，但不要求每个小节都完整拆成五块 contract。

### 1b 阶段：执行准备

与之前的网页agent模式不同，执行阶段由Codex控制本地设备或获批的临时Linux服务器运行，Claude Code承担独立审核职责，因此1b阶段大幅简化：
- 不再需要编写独立的"小节方案"和"提示词"
- Codex 确认方案每个 F 节描述足够具体，使代码实现无需猜测即可落地
- 检查跨 F 节文件传递关系（输入 / 输出 RDS、TSV 文件名前后一致）
- 为每个F节/gate输出资源评估，优先配置本地环境；仅在本地不可行时配置临时服务器、数据上传/下载和删除前同步规则
- 使用同一套R/Python锁文件、系统依赖清单、数据库版本、参数和seed管理本地与临时服务器环境
- 如有需要，对关键节使用五块 contract 模板结构化

## 2. 结构化 contract 模板

需要结构化时，每个 F 子节包含以下五块：

### input_contract

必须说明：
- required_inputs：必须读取的文件或对象
- optional_inputs：可选输入及其用途
- input_source：上游 F 节输出、本地数据文件或公共数据库下载
- input_validation：文件存在性、SHA256、shape、字段、样本/细胞数、基因 ID、表达单位、metadata 完整性
- blocking_input_failure：哪些输入失败会阻断执行

### method_decision_contract

必须说明：
- default_or_recommended_method：基于预审计的推荐方法
- method_selection_rules：根据真实数据结构如何选择方法
- methods_not_allowed_by_default：未满足条件时不得使用的方法
- required_approval_for_change：哪些变更必须用户批准
- sensitivity_or_fallback_methods：敏感性分析或降级路径
- interpretation_boundary：该方法最多能支持什么结论，不能支持什么结论

### output_contract

必须说明：
- core_audit_outputs：直接影响 gate 判定、方法选择或主要结论的核心表/报告
- reproduction_outputs：RDS、矩阵、模型对象、脚本、日志、source data、manifest 等复现文件
- figure_outputs：图、source data 和生成代码
- output_schema：关键输出字段、允许值、必填字段
- output_classification：正式manifest分别记录artifact_class（core/gate_decision/audit_trail）、publication_destination（main_text/supplement/not_planned/undecided）和review_priority（full/standard/spot_check）；不得用同一个Tier字段同时表达文件用途、论文去向和证据强度
- file_count_policy：核心审计文件优先控制在 5-8 个；补充复现文件可分目录组织

### gate_contract

必须说明：
- gate_name 和 gate_scope
- pass_conditions
- pass_with_limitations_conditions
- fail_conditions
- warning_handling
- researcher_approval_required
- next_step_allowed_if_pass

### claim_boundary

必须说明：
- allowed_claims：本小节结果允许支持的结论
- disallowed_claims：不得从本小节结果推出的结论
- required_limitation_sentences：必须保留的限制性表述
- evidence_level_candidate：该小节可能达到的证据等级

## 3. 执行环境选择与审计分层

Codex逐gate执行，默认执行优先级为：`laptop_thinkbook16p`（默认笔记本）→ `desktop_i5_14600kf`（备用台式机）→ 临时Linux服务器。每个F节必须维护一个 `reports/environment_setup/F{N}_execution_resource_assessment.tsv`，每个gate或analysis_module一行，记录输入规模、candidate_machine、machine_priority_rank、os_or_runtime、两台本地设备的实测可用资源、预计峰值RAM/磁盘/运行时间、GPU适用性、pilot结果、本地可行性、fallback_trigger、临时服务器最低和推荐配置、最终执行位置及用户审批状态。不得因为过去使用过某种服务器配置就沿用，也不得因为本地程序能启动就认定可安全完成。

默认笔记本不适合时必须先评估备用台式机；只有两条本地路径均不适合、备用设备当前不可用且等待不合理，或用户基于完整评估明确批准时，才可使用临时服务器。Windows原生可稳定支持的模块可原生运行；需要Linux依赖、编译链或与服务器统一用户态的模块可通过WSL2 Ubuntu 22.04或固定Linux容器运行。WSL属于对应宿主设备，不是独立算力，必须按宿主机实际分配给WSL的RAM、CPU、虚拟磁盘和I/O重新评估。服务器每次均按全新环境重新配置；正式运行前必须核对本地与服务器的R/Python包、外部工具、数据库、系统依赖、容器镜像、参数和seed。若Windows原生与Linux底层库不同，必须记录差异，不能只凭包版本号声明完全一致。

完成当前gate后必须暂停，产出gate报告、真实执行脚本、日志、输出文件、资源实测和manifest。无论在何处运行，关键结果最终必须保存到本地。临时服务器删除前必须完成文件数量、大小和SHA256核对，并生成 `reports/environment_setup/F{N}_{gate_id}_server_to_local_sync_manifest.tsv`；存在任何missing、size_mismatch或sha256_mismatch时禁止删除服务器。Claude Code审核后，由用户决定是否批准进入下一步。

### 文本编码和跨系统可读性

所有正式文本、脚本、Markdown、TSV、CSV、YAML、JSON和日志文件必须使用UTF-8编码保存。Windows PowerShell读取或写入中文文本时必须显式使用 `-Encoding UTF8`；R/Python脚本读写文本时应显式指定 `encoding = "UTF-8"` 或 `encoding="utf-8"`。WSL、Linux服务器和容器应设置或记录 `LANG=C.UTF-8` 或等价UTF-8 locale。机器可读表格的列名优先使用ASCII英文，中文说明放在note或Markdown报告中。若发现乱码、不可解析字符或跨系统换行/编码不一致，必须先修复并记录，不得继续基于损坏文本执行分析。

### 大文件下载和资源校验

大文件、慢速下载、需要断点续传或下载失败会阻断后续分析的资源，不得混在方案文本修改、代码重构或结果解读同一轮中临时下载。必须作为独立资源准备任务处理：先生成下载计划和预期大小/checksum清单，使用专门脚本、断点续传、日志、manifest和校验规则；下载完成后再更新资源状态。未完成大小校验、MD5/SHA256或gzip/readability检查的资源只能标记为pending或partial，不得进入主分析或被写成available。GSE239676和SRP444325的当前下载入口以 `scripts/download_resources/`、`reports/download_resources/` 和 `logs/download_resources/` 为准。

### 审计分层

1. **决策级审计**：影响方法选择、gate 通过、主要结论或解释边界的内容，必须严格审核。例如 DE 方法选择、CNV 恶性判定、MLMOD 评分阈值、pseudobulk 设计、Cox 模型、核心基因筛选。
2. **记录级审计**：文件命名、checksum、普通 manifest、非关键格式字段等，汇总审核即可，不应消耗主要精力逐项深挖。

每步 integrity check 建议不超过 10 项。若审计工作量开始超过实质分析价值，应优先保留决策级审计，压缩记录级审计。

### 关键中间对象保存

所有 .rds / .h5ad 对象保存到 `objects/` 目录。关键中间变量输出 shape / head / summary 到日志。git 追踪脚本和文本输出，大型二进制对象通过 manifest + SHA256 记录。

## 4. 证据等级与 claim_evidence_matrix.tsv

claim_evidence_matrix.tsv 不在 1a 阶段强制生成。建议在 F0-F8 分析完成、论文写作前，由 Codex 基于执行结果和审阅结果生成。

建议字段：
- claim_id, F_section, gate_id, claim_text, claim_type
- evidence_files, code_or_script_source, source_data_files
- statistical_support, effect_size_or_direction, biological_support
- reproduction_status, review_status
- evidence_level, allowed_manuscript_language, required_limitation_sentence, note

证据等级：
- not_supported：数据不支持或方向相反
- not_evaluable：关键数据缺失、质量不足或方法失败，不能评价
- exploratory_only：仅探索性、样本量不足、单方法结果或未复现结果
- single_cell_supported：单细胞层面有可复现证据支持
- bulk_supported：bulk 队列层面有可复现证据支持
- multi_cohort_validated：多个相对独立队列方向一致，且样本重叠风险、平台差异和统计模型已审计
- mechanistic_hypothesis：机制假设有数据关联或文献支持，但未被本研究实验验证

论文写作时，allowed_manuscript_language 必须与 evidence_level 匹配。关联性证据不得写成因果或实验验证；方向性观察不得写成独立验证。

## 5. 数据先于方法

在制定或执行任何分析方案前，必须先摸清数据结构。方法、参数和解释强度必须由真实数据决定，而不是由文件名、常用套路或 agent 偏好决定。

典型要求：
- 单细胞：先审计 metadata、QC 字段、作者注释、raw/processed 状态和已有处理
- bulk：先审计表达单位、log 状态、平台、probe 映射、临床终点、事件数和样本重叠
- 多组学：先审计来源、版本、genome build、样本匹配和缺失率
- 外部验证：先确认是否真的含有所需分组、终点或表达数据，不能因数据集知名就预设可验证

若数据结构与预期不一致，必须先更新方法计划，再执行分析。

## 6. 反事实前提检查

12 维度框架适合检查方案的内部质量和一致性，但不能替代对核心前提的质疑。增量审核容易陷入"验证模式"——检查改动是否正确落地，而忽略被改动的内容本身是否建立在正确的前提上。

规则：每个 F 大节 Gate 通过审核前，Codex 必须在结果解读中完成一次反事实前提检查，Claude Code 必须在独立审核中复核该检查是否充分：

1. 识别该 F 节依赖的核心假设（不限于一个）
2. 假设该假设为假，评估当前 F 节的分析还能支撑什么结论
3. 如果答案是"几乎不能"，则该假设必须在 gate 内有可验证的检验或对照设计，而不是被默认为真
4. 如果 gate 内已有相关检验，评估该检验是否真正测试了假设本身，还是只测试了假设的某个推论或副产品

典型反事实问题：
- F2："如果 MLMOD 签名与通用 OXPHOS / 缺氧签名高度共线，高 MLMOD 亚群是否仍然是功能独特的？"
- F2.4："如果 bulk 预后效应在调整肿瘤纯度后消失，F2-Gate4 是否应该 PASS？"
- F3.2："如果恶性上皮中不存在真实的分化轨迹，拟时序分析的输出有什么价值？"
- F8.3："如果 CellOracle 的基因调控网络推断本身不可靠，虚拟扰动结果能支撑什么？"

该检查与 12 维度中的"科学假设与逻辑链"互补而不重复：维度 1 检查推理链是否有跳跃，反事实检查问如果起点就错了会怎样。

## 7. Gate 标准

* 通过 gate 的唯一标准：**用户明确确认**
* Codex 和 Claude Code 可以建议是否通过，但最终由用户裁决

## 8. 跨 F 节循环定义防范

单 F 节内的循环定义容易发现（维度 8），但跨多个 F 节的循环链更隐蔽——每个单独的 F 节看起来都合理，但串起来可能构成"用自己的定义验证自己"。

### 本项目的主要循环风险链

F2（MLMOD签名、主分数和高低状态）→ F2.3/F3/F4（用该状态发现marker、通路和LR轴）→ F5（综合上游证据筛选核心基因）→ F6/F7/F8（用核心基因继续做免疫、多组学和单基因分析）

**风险：如果 MLMOD 签名实际上主要捕获了通用应激/氧化磷酸化信号，那么 F5-F7 的整条链都是在验证这个偏差，而不是独立发现。**

### 必须在方案中设计的对照检验

| 检验位置 | 检验内容 | 不通过时的后果 |
|---------|---------|-------------|
| F2 | MLMOD score vs 参照签名（OXPHOS / hypoxia / apoptosis）相关性 | specificity_status 降级，影响全项目解释上限 |
| F2 | MLMOD score vs nCount_RNA / nFeature_RNA / percent.mt 相关性 | 如果主要由技术因素驱动，先回查QC、signature和输入层；不得机械回归后宣称问题消失 |
| F2.3 | 残差分析：去除参照签名贡献后 MLMOD 残差是否仍有生物学意义 | 如果残差无意义，MLMOD 不具有独立性 |
| F4 | LR轴中的配体/受体是否直接属于MLMOD signature或F2 marker | 样本层主证据必须标记循环定义；严重重叠最多探索性 |
| F5 | 核心基因是否因同一F2/F3证据重复提升层级 | 同一来源不得在证据分层或tie-break中重复计入 |
| F6/F7/F8 | 是否复用同一bulk队列、同一scRNA reference或同一状态定义并称为新增验证 | 标记same_data_method_robustness，不得升级独立证据等级 |
| 外部验证 | 验证队列是否反向参与signature、参数、阈值、候选或排序规则选择 | 一旦参与即不再是最终验证队列，必须另找独立数据 |

### 1b 总体大纲审核时的跨节追溯

1b 阶段制定执行顺序时，必须画出 F 节之间的数据依赖图（哪个 F 的输出是哪个 F 的输入），检查：是否存在路径使得某个 F 节的核心结论通过下游 F 节回流验证自身的输入假设。

## 9. 负面 / 意外结果处理

当某个分析步骤产生负面结果（如无显著差异、无明显聚类结构、预后无关联）时，按以下顺序排查：

1. **审视方法适配性**：该分析方法是否适合当前数据和科学问题？如果方法本身不适合，换用更合适的方法
2. **合理调整分析参数**：方法适合但参数可能不优，在有合理生物学或统计学解释的前提下调整参数。注意：不允许无理由地反复调参直到出现显著结果（p-hacking）
3. **检查上游输入**：上一步的输出是否有问题？回溯检查上游 F 节的数据质量、处理流程
4. **确认真实负面结果**：如果上述排查均无问题，说明确实不存在显著差异——如实记录该发现，调整下游 F 节计划

核心原则：目的是区分"分析方法的问题"和"数据本身的真实信号"。负面结果本身是有价值的科学发现，不应被掩盖或无限制地重新分析。

## 10. 证据与推理的边界

* **agent 意见是推理（reasoning），不是证据（evidence）**——多个 AI agent 互审可能共享系统性偏差
* 每个关键结论必须追溯到三类实证依据之一：
  1. 数据文件（actual data output）
  2. 运行代码 / 脚本 / 日志（reproducible computation）
  3. 真实文献 / 数据库（external validation）
* agent 的分析和建议可以辅助决策，但不能替代上述实证依据
* **阶段一适用方式**：方案制定阶段尚无数据输出和代码运行，此时方法选择必须有文献支撑——引用具体论文或工具官方文档，说明该方法在类似数据/问题上的验证记录，并论证其适合本研究的具体理由。不能只写"推荐使用 X"或"X 是常用工具"

## 11. QC 要求（由 F0 审计结论驱动，不写死）

* Doublet 检测：F0 先确认数据集是否已有 doublet 检测结果及其可信度；若需独立重做，scDblFinder按样本作为预注册主方法，DoubletFinder仅作敏感性/异常复核；不要把Xi & Li 2021错误归因为“scDblFinder综合最优”
* Ambient RNA 校正：F0 先评估 cross-expression 水平和原作者校正记录；若需补做，推荐 DecontX/SoupX，在归一化之前完成
* 其他 QC 步骤：不预设"必须做"或"可以跳过"，根据 F0 审计报告中的具体发现决定

## 12. 差异表达

* Pseudobulk：所有涉及差异表达的分析必须避免 cell-level 伪重复；优先使用 sample/patient 级 pseudobulk 聚合或样本级模型；DESeq2 仅限 raw/integer count 或获批 tximport 兼容输入，processed microarray、count-like 小数矩阵或其他数据类型按主线方案使用获批模型
* CNV 独立报告：inferCNV 和 CopyKAT 结果分别报告，不合并为统一 support level
* inferCNV按sample_id × epithelial_cluster_id解释；CopyKAT逐样本运行；两者同源于RNA表达，只提供方法稳健性而非独立DNA验证
* sample_id固定/随机效应按设计决定：同一样本内高低状态可用`~ sample_id + state`；condition与sample完全嵌套时不得使用秩亏的`~ condition + sample_id`；混合模型不是pseudobulk的自动上位替代

## 13. 签名冻结

* 签名冻结在 bulk 验证前：防止 p-hacking
* GSE235046/SRP444325：F2.1主路线是获批后SRA重处理（STAR/RSEM/tximport/DESeq2）；GEO公开小数count-like表只能作为limma-voom条件fallback，不得四舍五入后作为主DESeq2输入
* interaction/Torin rescue 不决定主signature准入，只作为annotation字段；主signature按原文三比较标准和目标数据适用性冻结
* UCell为单细胞MLMOD唯一主分数，MLMOD_Score固定等于UCell_MLMOD_score，主maxRank冻结为1500；AUCell为关键rank-based敏感性，aucMaxRank = ceiling(0.05 × nGenes)，AddModuleScore、singscore、条件性ssGSEA/JASMINE为其他敏感性；不做多算法平均或投票
* F2采用两层筛选：第一层在全细胞主要大类中筛查MLMOD信号分布，输出F2_candidate_cell_class_decision.tsv并暂停等待研究者批准；第二层只在获批候选大类内部定义MLMOD-high/low状态。当前主线优先假设为malignant_epithelial_main，但必须接受第一层反证；若主要信号不在恶性上皮，不得强行沿恶性上皮路线执行。F1完全不使用MLMOD分数、基因集或预后信息参与聚类、注释和恶性判定。
* 主线MLMOD-high/low定义优先采用patient-stratified top/bottom 20%；patient_id不可用或不足时使用sample-stratified top/bottom 20%。Global阈值（Q3、top10%、mixture交叉点等）只作敏感性或展示。主对照为MLMOD_low_reference，中间60%为intermediate，不进入主high-vs-low DE。
* Ferroptosis / lipid oxidation / lipid peroxidation为主机制支持模块，用于判断MLMOD-high是否更接近线粒体局部膜氧化损伤活性状态；基因集优先来自MSigDB GOBP_FERROPTOSIS、GOBP_LIPID_OXIDATION、FerrDb最新版和Cell 2025原文机制锚点。Cuproptosis和pyroptosis为对照/混杂死亡方式模块，不得与ferroptosis/lipid peroxidation平级作为主线机制结论；pyroptosis在髓系细胞分析中尤其需要作为控制模块。Apoptosis、necroptosis、stress、cell cycle、ribosomal、MT_transcript_burden等为其他对照/混杂模块。
* 主分析不默认删除MT-encoded genes，但必须计算MLMOD_Score_no_MT_encoded，即从冻结签名中排除^MT-基因后用相同UCell参数重新打分。必须计算MT_transcript_burden_score作为混杂/解释变量，禁止命名为MLMOD_score_MT_encoded_only。若MLMOD_Score full高但no_MT_encoded后完全消失，解释必须降级为mitochondrial transcript burden-associated state。
* F2.3必须输出MLMOD_mechanism_interpretation_matrix.tsv，按证据强度决定允许使用的最高表述。只有no_MT_encoded稳定、ferroptosis/lipid peroxidation支持，且cuproptosis/pyroptosis/apoptosis/stress/QC/patient bias均不能解释，并且bulk验证通过时，才允许最高表述为prognosis-associated MLMOD-high state。
* 最终验证队列不得参与signature、主参数、阈值、候选或排序规则调整

## 14. 分析设计原则

以下 10 条是所有具体方法学规则的上位指导。具体规则规定"怎么做"，这 10 条规定"怎么想"。撰写方案和审核时，先对照这 10 条检查设计思路，再落实具体规则。

### 1. 先定生物学问题，再选算法

不要一开始就把重点放在"用什么算法"，而应先明确：研究想寻找的生物学现象是什么、它可能出现在哪些细胞类型或样本背景中、它可能被哪些技术因素或混杂因素伪装出来。

### 2. 两层筛选：全局观察→候选细化

对于细胞状态、功能程序、疾病相关亚群或预后相关信号，应尽量采用"两层筛选"思路：先在全局层面观察信号主要富集在哪些细胞大类、样本或条件中，再在候选细胞大类或候选样本背景内进行更细致的二次分析。不要在没有全局筛查的情况下过早限定研究对象。

### 3. 聚类 ≠ 真实生物学亚群

聚类只能说明细胞在当前特征空间中相似，不能单独证明它们构成稳定、可解释、可推广的生物学实体。是否有生物学意义，需要结合 marker、功能打分、QC 指标、患者/样本分布、敏感性分析和外部验证共同判断。

### 4. 复杂概念拆成可解释模块

对复杂生物学概念，应尽量拆成多个可解释模块，而不是只计算一个总分。例如，MLMOD 状态可能同时包含目标生物学程序（线粒体膜氧化损伤）、通用应激反应、细胞周期、低质量细胞、污染、患者偏倚等成分。应将主信号、支持信号和混杂信号分开打分和解释。

### 5. 敏感性分析对应具体质疑

敏感性分析不应只是机械地"多跑几版"，而应对应具体质疑。每一种敏感性分析都应回答一个明确问题，例如：结果是否依赖 MT-encoded 基因？是否由 QC 指标驱动？是否由细胞周期、应激、凋亡、污染、doublet 或患者/样本偏倚解释？是否依赖某一种打分方法、聚类参数或特征选择方式？

### 6. 同 lineage 内比较

在比较 high/low 状态时，应优先在同一细胞大类内部定义，而不是直接跨不同细胞类型比较。全细胞层面的打分适合用于初筛信号富集位置；真正定义功能状态或提取特征基因时，应尽量在同一 lineage、同一大类细胞或合适的分层背景内进行。

### 7. 特征基因审计后再提取

特征基因应在候选状态经过基本审计后再提取。提取 marker 时，应特别标记或过滤可能由技术因素、低质量、污染、应激、细胞周期、核糖体负荷、线粒体比例或患者特异性造成的基因。最终用于机制解释或 bulk 预后验证的 signature 应尽量是 clean signature，而不是明显的伪影基因集合。

### 8. Clean signature 建模

对于预后模型或外部验证，不应直接把未经审计的单细胞 marker 全部拿去建模。应优先使用跨患者稳定、非 QC 主导、非污染主导、有机制解释、在目标细胞类型中定位明确的 clean genes，并在 bulk 队列中进行 Cox、KM、临床协变量校正和外部队列验证。

### 9. 预设解释等级

在分析前应尽量预先设定解释等级：什么结果可以强支持主要假设，什么结果只能保守表述，什么情况提示结果可能是技术伪影，什么情况需要降级解释或暂时不作为主线推进。避免跑完结果后按显著性倒推故事。

### 10. 保守、可审计、可复现

好的生信分析不是简单跑出显著结果，而是逐步证明该结果不是技术伪影、不是患者偏倚、不是算法产物，而是能被多层证据共同支持的生物学现象。

## 15. Harmony 整合后恶性上皮评估

Harmony 整合后恶性上皮细胞按 sample_id 独立成簇 **不一定是整合不足**——恶性上皮的患者特异 CNV 和克隆状态本来就可能导致分离。必须交叉验证后判断：

| 判断维度 | 指向合理生物学分离 | 指向整合不足或质量问题 |
|---------|-----------------|-------------------|
| **影响范围** | 仅恶性上皮或个别特殊亚群按样本分离；免疫/基质细胞混合良好 | 几乎所有细胞类型（包括免疫细胞）都按样本独立成簇 |
| **CNV/突变信号** | 分离的恶性群有明确患者特异 CNV（inferCNV 对应），其他患者无此模式 | 分离的群没有清晰 CNV 模式，或同一患者出现异常分散的非恶性细胞 |
| **标记基因与功能** | 高表达已知肿瘤特异性基因、谱系标志或增殖/干性程序，生物学可解释 | 高表达线粒体基因、核糖体基因、解离应激基因，或出现双细胞特征 |
| **同一患者内部一致性** | 同一患者恶性细胞聚集但内部仍有亚结构（细胞周期、亚克隆） | 同一患者所有细胞聚成极度致密单簇，提示未完全移除的批次效应 |
| **与外部数据比较** | 外部相同癌种数据集中也观察到类似患者间分离 | 与独立数据整合后该患者仍完全孤立，且无生物学依据 |

### 实际操作流程

1. **分细胞类型评估**：先只对非恶性细胞（免疫、基质）做 sample_id 着色——若混合良好，说明整合技术层面成功；然后再看恶性细胞
2. **无监督聚类交叉检查**：恶性上皮各 cluster 的样本构成如果呈现"一个 cluster 主要来自一两个患者"，在高异质性癌症中常见。进一步计算差异基因——若富集在特定染色体区域，即为 CNV 驱动的异质性，是重要发现
3. **排查假生物学分离**：如果某样本的恶性细胞簇高表达热休克蛋白（HSP）、解离相关基因（FOS、JUN）或线粒体基因占比异常，需怀疑组织处理/保存质量差异，回归 QC 指标（基因数、UMI 数、线粒体比例）排查

## 16. 关键中间对象的独立 quality gate

方案不能只按"常规流程顺序"列出分析步骤（QC → 聚类 → 注释 → 下游分析）。对每个关键中间对象都要问：**这个对象是否会作为后续分析、分组、统计或生物学解释的单位？** 如果会，必须在它产生后设置独立 quality gate，包含以下 6 项：

1. **检查维度**：该对象需要检查哪些质量指标
2. **失败模式**：每类问题的具体判定标准
3. **Fallback 路径**：每类问题对应的处置方案（回退到哪一步、怎么调整）
4. **输出文件**：质量审查结果的结构化输出（TSV 表格）
5. **暂停条件**：什么情况下必须暂停流程、等待人工复核
6. **下游准入规则**：后续步骤以该 gate 的输出作为准入依据，不得绕过

### Cluster-level QC gate（聚类完成后、细胞注释前）

聚类结果是后续所有分析（注释、亚群提取、DE、MLMOD 评分、细胞通讯）的基础单位。不能默认聚类结果可以直接用于注释或下游分析。必须在聚类完成后、注释开始前设置 cluster-level QC gate。

#### 逐 cluster 检查维度

| 检查项 | 判定标准（方案中须具体化） |
|-------|----------------------|
| **细胞数** | 是否过少（如 < 30 cells），影响下游 DE 统计功效 |
| **跨 resolution 稳定性** | 在相邻 resolution（如 0.4/0.6/0.8）下是否稳定存在，还是只在特定 resolution 出现 |
| **Marker 清晰度** | 是否有明确的 top marker，有无互斥谱系标志共表达（如同时高表达 T 细胞和 B 细胞 marker） |
| **Doublet 富集** | doublet score 是否显著高于其他 cluster |
| **Ambient RNA 信号** | 是否高表达其他细胞类型的 marker（提示 ambient RNA 污染） |
| **低质量 / 应激信号** | 线粒体基因比例、核糖体基因比例、血红蛋白基因（HBB/HBA）、热休克蛋白（HSP）、解离应激基因（FOS/JUN）是否为主要驱动 |
| **批次 / 样本 / 患者主导** | 是否由单一 sample_id 或 batch 主导（参照 §15 Harmony 评估框架判断是否为真实生物学分离） |
| **细胞周期主导** | S/G2M score 是否为该 cluster 区分于邻近 cluster 的主要特征 |
| **Resolution 粒度** | 是否存在过粗（明显异质的 cluster 未被拆分）或过细（生物学无意义的拆分）迹象 |

#### 问题处置路径

每类问题必须有预定义的处置路径，不得用通用的"调整 resolution"替代具体问题的处理：

| 问题类型 | 处置路径 | 禁止的替代 |
|---------|---------|----------|
| Doublet 富集 cluster | 回到 QC，加强 doublet 检测和过滤，重新聚类 | 仅调高 resolution 拆开 |
| Ambient RNA 驱动 cluster | 回到 QC，加强 ambient RNA 校正（DecontX/SoupX），重新聚类 | 仅调高 resolution 拆开 |
| 低质量细胞驱动 cluster | 回到 QC，收紧质量过滤阈值，重新聚类 | 仅排除该 cluster 但不检查其他 cluster 是否受污染 |
| 整合失败（非恶性细胞按样本分离） | 回到整合步骤，调整 Harmony 参数或换整合方法 | 仅调 resolution |
| 细胞周期主导 cluster | 评估是否需要回归掉细胞周期效应后重新聚类 | 直接忽略或合并到邻近 cluster |
| 过粗 / 过细 | 调整 resolution 或尝试多 resolution 策略 | （此时调 resolution 是正确处置） |
| 互斥 marker 共表达 | 怀疑 doublet 或 ambient RNA，按对应路径处理；若排除后仍存在，保留但标注并降级解释 | 直接注释为某一谱系 |
| 人工无法判断 | 暂停，标注为待人工复核，等待用户决策 | 自行拍板 |

#### 结构化输出

所有 cluster-level QC 结果必须输出以下文件：
* **`cluster_quality_review.tsv`**：每行一个 cluster，列出所有检查维度的结果（数值 + 判定）
* **`cluster_quality_decision_matrix.tsv`**：每行一个 cluster，列出最终决策（PASS / FAIL-回退路径 / WARNING-降级使用 / HOLD-待人工复核）

这两个文件是后续注释、目标细胞提取、恶性判定、MLMOD 打分和下游分析的准入依据。后续步骤不得绕过该 gate——必须引用 decision_matrix 中的判定结果，仅对 PASS 或 WARNING 的 cluster 进行下游分析。

### 其他需要独立 quality gate 的中间对象（非穷举）

以下中间对象同样可能需要独立 quality gate，具体是否设置由方案设计时根据分析链路判断：
* **CNV 分类结果**（恶性 vs 非恶性判定）——作为后续所有恶性细胞分析的基础
* **细胞注释结果**——作为所有 cell-type-specific 分析的基础
* **MLMOD 评分 / 状态定义**——作为 F2.3-F8 整条下游链路的基础
* **Pseudobulk 聚合后的 pseudo-sample 矩阵**——作为 DE 分析的输入单位

每个 gate 均须满足上述 6 项要求（检查维度、失败模式、fallback、输出文件、暂停条件、下游准入规则）。

## 17. 方案撰写常见错误防范

以下是生信方案中常见的质量问题。Codex 撰写方案时必须主动避免，Claude Code 审核时必须主动检查：

### 1. 方法堆砌

同时写大量方法（如 WGCNA + LASSO + SVM-RFE + random forest + XGBoost + Cox + nomogram + immune infiltration + CellChat + MR + docking）看起来高级，但：
* 每个方法之间必须有清晰的逻辑关系和数据流转
* 不允许"生信八股文大礼包"式罗列——每个方法必须回答具体的科学问题
* 方案中写明：为什么选这个方法、它回答什么问题、它的输出如何驱动下一步

### 2. 样本量不支持复杂模型

LASSO / random forest / XGBoost / SVM / neural network / nomogram 等机器学习方法需要足够样本量：
* 选用复杂模型前必须评估：训练集样本数、事件数、特征数的比例是否合理
* 几十个样本做复杂模型极易过拟合——优先选择简单模型或降维后再建模
* 必须有独立验证集，不能只靠交叉验证声称泛化能力

### 3. 相关 ≠ 因果

* 不允许将关联关系直接表述为因果关系
* 错误："某基因高表达导致胃癌进展"
* 正确："某基因高表达与不良预后显著相关，提示其可能参与胃癌进展，需实验验证"
* 所有 claim 必须匹配其证据层级（见 §4 证据等级）

### 4. 细胞通讯过度解释

CellChat / CellPhoneDB / NicheNet / LIANA 的结果是基于配受体数据库的推测：
* 错误："A 细胞通过某通路激活 B 细胞"
* 正确："推测 A 细胞与 B 细胞之间可能存在某配体-受体介导的相互作用"
* 互作结果不能作为独立证据，只能作为假说生成的线索

### 5. 拟时序 ≠ 真实发育时间

拟时序根据表达相似性推测状态转换，不等于真实时间轴，尤其在肿瘤中：
* 错误："细胞从 A 分化为 B"
* 正确："A 与 B 可能处于连续的转录状态变化中"
* 拟时序方向需要生物学先验知识验证，不能仅靠算法默认方向

### 6. Marker 缺乏医学解释

筛出的 marker 基因必须检查是否为技术 artifact 或无生物学意义：
* 是否核糖体基因（RPS/RPL）？
* 是否线粒体基因（MT-）？——本项目尤其需要关注，MT-encoded 基因可能反映 MLMOD 签名的混杂成分
* 是否应激/凋亡基因？
* 是否细胞周期基因？
* 是否正常胃上皮分化 marker（而非肿瘤特异）？
* 是否患者特异性驱动（某个患者贡献绝大多数细胞）？
* 方案中必须包含 marker 过滤和生物学验证步骤

### 7. 忽视批次效应和混杂因素

单细胞数据常见混杂必须在方案中有对应处理策略：
* 患者来源、样本批次、测序平台
* 肿瘤/正常组织比例、测序深度
* 线粒体比例、细胞周期、doublet
* 炎症/应激状态
* F0 审计时必须评估这些混杂因素的严重程度，F1 方案中必须有对应的 QC 或校正策略

## 18. 方案伪具体性检测

方案的大框架和解释边界可以很强，但如果核心模块把真正决定结果的规则推迟到"执行时再定"，则方案实质上仍是空壳。这种"看似写了方法和阈值，实际靠临场判断"的问题不能靠执行阶段的安全检查弥补——阶段一就必须做真正的方法研究。

### 合理的自适应规则 vs 伪具体方案

不是所有"需按数据决定"都是问题。关键区别：

**合理的自适应规则**（允许）必须同时写清 5 项：
1. **输入证据**：基于什么数据/指标做判断（如"根据 silhouette score 和已知 marker 表达"）
2. **候选范围**：备选方案有哪些（如"resolution 在 0.3-1.2 之间搜索"）
3. **选择准则**：用什么标准在候选中选择（如"选 silhouette score 最高且关键 marker 不被拆分的 resolution"）
4. **失败条件**：什么情况下判定该步骤失败、需要回退或换方法（如"如果所有 resolution 下 marker 均被拆分，考虑换用 SC3 或手动合并"）
5. **输出记录**：决策过程如何记录（如"输出所有候选 resolution 的对比表 + 最终选择理由"）

**伪具体方案**（必须打回）的特征：
* 用模糊修饰词替代可复核判据："综合考虑""明显""稳定""适当""强证据""合理的""足够的"
* 看似写了方法、阈值或 gate，但实际规则无法被第三方独立复核
* 引用了工具名但没有说明参数选择理由，也没有查阅工具文档或相关文献
* "根据实际情况调整" 后面没有调整范围、调整依据和调整记录要求

### 阶段一方法研究的实质要求

方案中的方法选择必须体现真正的方法研究，不能仅靠 agent 常识或"标准流程"。写具体方案前，必须主动做以下检索：

1. **检索高分文献**：搜索近 2-3 年高影响力期刊（如 Nature、Cancer Cell、Genome Biology）中同类分析（胃癌 scRNA-seq / MLMOD 或类似损伤表型 / 预后 signature 构建）的论文，看高分文献在同一步骤上选了什么方法、什么参数、怎么论证，作为方案设计的参照
2. **查阅工具官方文档**：读工具的 vignette / tutorial / README 中的参数说明、推荐设置和已知局限，尤其关注"what this tool does NOT do"和"when NOT to use this tool"
3. **查阅工具原始论文**：了解算法的适用条件、benchmark 结果和作者自己承认的局限性
4. **结合本数据特征论证**：基于 F0 审计结果（细胞数、基因数、批次结构、样本量），论证为什么选这个方法/参数而不是替代方案

方案中引用方法时，必须附上依据来源（如"参照 [Author, Year, Journal] 中对类似规模数据集的处理"或"根据 Seurat v5 vignette 推荐"），不能只写"使用 X 工具"或"推荐使用 Y 方法"

### 审核检测方法

对方案中每个关键决策节点，问：
1. 如果把这段方案交给另一个不了解上下文的 agent，它能否按方案独立做出相同决策？如果不能，缺的是什么？
2. 方案中的方法选择是否有文献或工具文档支撑，还是仅凭 agent 推理？
3. 阈值和参数是来自数据特征或文献推荐，还是凭空写了一个"默认值"？

如果答案是"不能独立复核"，该节点必须补充具体判据，或标注为"待 F0 审计后确定"并写明确定的完整流程（输入→候选→准则→失败→记录）。
