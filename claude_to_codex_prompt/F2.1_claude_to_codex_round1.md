# Codex修改指令：F2.1第三方审查修订

## 背景

第三方审查者审查了重写后的F2.1-F2.4，确认整体质量很高。但发现一个关键缺口：F2.1完成了ortholog映射和检出率过滤，证明了"这些基因在人胃癌上皮中表达"，但没有验证"这些基因在上皮细胞中是否仍然作为一个coherent module协同工作"。跨物种跨细胞类型适用性需要进一步验证。

## 修改内容

请在F2.1的第七步（低特异性风险审计）之后、第八步（外部候选集审计）之前，新增一个步骤：

**"第七步b：跨物种跨细胞类型适用性验证"**

内容如下：

> 第七步b：跨物种跨细胞类型适用性验证。MLMOD签名来自小鼠BMDM bulk RNA-seq，应用于人胃癌恶性上皮单细胞数据。ortholog映射和检出率过滤只证明了基因在目标细胞中"存在"，但不能证明它们在目标细胞中"协同工作"。Biomni必须在06a_malignant_epithelial_main.rds中对最终MLMOD_human_scoring_signature完成以下三项验证，结果记录在MLMOD_cross_system_validation.tsv中：
>
> （1）模块共变性检查：计算签名基因在恶性上皮细胞中的平均pairwise Spearman相关系数。若平均相关系数极低（例如<0.05），说明这些基因在胃癌上皮中几乎不共变，打分结果可能只是无关基因的噪声平均值，应作为Gate1 warning记录。若平均相关系数在合理范围（单细胞数据中0.10-0.30已属于有意义的共变），支持签名在目标细胞中具有模块性。此外，若条件允许，可使用WGCNA module preservation的Zsummary统计量做更正式的检验（Zsummary>10强保守，2-10中等，<2不保守），但不作为强制要求。
>
> （2）随机基因集对照（permutation test）：随机抽取与MLMOD签名同样数量的基因（从恶性上皮表达基因中抽取），重复至少1000次，每次用相同打分方法计算随机评分。比较真实MLMOD_Score的方差或细胞间分布宽度（例如IQR或SD）是否显著大于随机期望（permutation p-value < 0.05）。若真实签名与随机签名无显著差异，说明打分在目标细胞中没有超出背景噪声的信号，应作为Gate1 warning记录。
>
> （3）签名基因功能富集验证：对MLMOD_human_scoring_signature基因集本身（不是高MLMOD亚群的差异基因）做GO和KEGG富集分析。检查富集结果是否仍然指向线粒体功能、膜损伤、氧化应激、mTOR信号等与mitoxyperiosis机制相关的生物学过程。若富集到的主要通路与原始机制无关（例如全部是核糖体、细胞周期或无关代谢通路），说明签名在跨物种跨细胞类型迁移后生物学含义可能已经漂移，应作为Gate1 warning记录并在方法学限制中说明。注意：这一步和F3.1的功能富集不同——F3.1是对"高MLMOD亚群差异表达基因"做富集，本步是对"签名基因集本身"做富集，回答的是不同问题。
>
> 三项验证结果必须写入MLMOD_cross_system_validation.tsv，字段至少包括validation_type、metric_name、metric_value、threshold_or_benchmark、result_interpretation、warning_flag和note。三项中任一出现warning的，必须在F2_gate1_signature_construction_report.md中标记并说明是否影响主评分可信度；但warning本身不自动阻断F2.2，因为跨系统迁移本质上是探索性的，只要方法学限制写清楚即可。

同时请在F2-Gate1（当前约第451行）的通过条件中增加：

> 跨物种跨细胞类型适用性验证完成（MLMOD_cross_system_validation.tsv存在且三项验证均有结果）

并在F2.1的输出清单中增加 `MLMOD_cross_system_validation.tsv`。
