### 修订 1：SHA256 比较统一使用 .lower()

**问题**：主线方案第113行要求 SHA256 比较不区分大小写。当前脚本中 sha256_file() 返回小写（hashlib 默认），download_manifest.tsv 中存储大写。execute() 中 tar SHA 比较已有 .lower()，但 build_data_audit() 中的 precheck 字段比较、build_processed_manifest() 中的 SHA 和其他所有涉及 SHA256 的比较没有统一处理。

**修改要求**：
1. 在 build_data_audit() 的 compare_fields 循环中，对 gene_order_sha256 字段比较加 .lower()。
2. 所有涉及从外部 TSV 读取的 SHA256 与 sha256_file() 产出的比较，统一双侧 .lower()。
3. F0 输出的 SHA256 字段统一存储为小写，在工具函数或脚本注释中说明这个约定。

### 修订 2：GSE239676 数据结构预审计补齐

**问题**：GSE239676 在 results/F0_audit/ 下的两个预审计表（non_GSE183904_data_structure_precheck.tsv、predownloaded_resource_structure_audit.tsv）中完全缺失。虽然 download_manifest 和 GSE239676_download_manifest.tsv 记录了下载状态（4个文件 size_ok），但从未做过数据结构预审计——没有样本数、细胞数、基因数、矩阵格式、metadata 字段等信息。

**本地已下载文件**：
- data/public_downloads/GSE239676/GSE239676_count_matrix.mtx.gz (~985MB, gzip_read_ok)
- data/public_downloads/GSE239676/GSE239676_barcodes.tsv.gz (~5.4MB, plain_text_read_ok_gz_suffix)
- data/public_downloads/GSE239676/GSE239676_features.tsv.gz (~55KB, plain_text_read_ok_gz_suffix)
- data/public_downloads/GSE239676/GSE239676_meta.tsv.gz (~5.5MB, plain_text_read_ok_gz_suffix)
- data/public_downloads/GSE239676/GSE239676_series_matrix.txt.gz (~6KB)
- data/public_downloads/GSE239676/GSE239676_suppl_listing.html (~890B)

**修改要求**：
1. 在 F0 执行前，写一个独立的轻量 Python 脚本（标准库 + gzip），对 GSE239676 做流式预审计：
   - 读 barcodes.tsv.gz 数行数（细胞数）
   - 读 features.tsv.gz 数行数（基因/特征数）和前几行内容（确认基因ID类型）

2. 将结果追加到 predownloaded_resource_structure_audit.tsv（遵循该表既有字段结构）
3. 预审计脚本保存为 scripts/F0_setup/preaudit_gse239676.py

5. 结合 project_overview.txt 已知信息（Gastroenterology 2024, 20例IV期胃腺癌, 含原发/肝转移/腹膜癌播散, GEO提供count_matrix.mtx与metadata），验证实际数据是否与已知描述一致，不一致处需记录

### 修订 3：audit_csv_gz() 整数性检测严谨化

**问题**：当前整数性检测使用 re.search(r"[^0-9,]", values) 做近似判断。虽然对 GSE183904 的已知纯整数矩阵足够，但如果数据出现浮点数（如 3.5）、科学计数法（1e5）、负数（-1）或带引号的数值，该正则的行为不够精确。F0 的整数性判断直接驱动 F1 QC 方法选择——如果这里误判，后续修复成本很高。

**修改要求**：
1. 对 values 字段逐值解析（split by comma），去引号后尝试：
   - 先检查是否为空字符串（缺失值）
   - 尝试 int() 转换：成功 → 整数
   - 失败则尝试 float() 转换：成功 → 非整数（浮点/科学计数法）
   - float 也失败 → invalid（非数值）
2. 统计三类异常：missing_value_count、noninteger_float_count、invalid_nonnumeric_count（取代当前的 missing_value_rows、invalid_numeric_value_rows）
3. 负整数也要单独统计为 negative_integer_count，因为 scRNA count 矩阵不应出现负值
4. 不需要改变整体判断逻辑——只要 noninteger_float_count == 0 && invalid_nonnumeric_count == 0 && negative_integer_count == 0 && missing_value_count == 0，仍判定为 nonnegative_integer_count_like
5. 保留 scan_seconds 和性能意识——逐值解析会比正则慢，但 F0 只扫 40 个 csv.gz（合计约 158K cells × 26K genes），在流式读取下预计仍在数十分钟以内可完成；如果对性能有顾虑，可以用采样策略（如每个文件前 1000 行全量解析 + 剩余行正则快速扫描），但必须在 data_audit.tsv 中记录采样策略
6. 更新 data_audit.tsv 字段定义，新增字段名对齐修改后的统计变量
7. 确保 data_audit.tsv 新字段与 precheck 表的 compare_fields 比较逻辑兼容——precheck 表中的旧字段名（missing_value_rows、invalid_numeric_value_rows）和新字段名之间需要有映射或容错

### 修订 4：marker panel 内容审计加入 F0 脚本

**问题**：当前 F0 脚本只检查 cell_type_marker_panel.tsv 文件是否存在（gate checklist 的 marker_panel 项），不检查内容。主线方案 F0.1 说"如发现marker冲突或缺失，只输出问题清单"。轻量内容审计放在 F0 可以早发现问题。

**已知 marker panel 信息**：

- cell_marker_reference_evidence.tsv：71 条证据记录（含表头 72 行）

**修改要求**：
1. 在 F0 脚本中添加一个 audit_marker_panel() 函数，检查：
   - cell_type_marker_panel.tsv 必需字段完整：cell_type, positive_markers, minimum_rule, confidence, evidence_ids
   - 每行 positive_markers 非空
   - 每个 cell_type 不重复
   - positive_markers 中的基因名是否为有效格式（大写字母开头，只含字母数字和连字符）
   - evidence_ids 中引用的 ID 是否在 cell_marker_reference_evidence.tsv 中存在（交叉引用完整性）

4. 在 analysis_log.md 中记录审计结果

### 修订 5：F0 脚本拆分为多个阶段性脚本

**问题**：当前 run_F0_full_audit.py 1694 行作为单体脚本，一次执行完所有 F0 任务。研究者和审核者希望能分步执行、分步审核，及时发现问题。

**修改要求**：

   - 输出：project_structure_ready.txt, processed_input_manifest.tsv, analysis_log.md 开始

2. **scripts/F0_setup/F0_step2_sample_info_and_audit.py**

3. **scripts/F0_setup/F0_step3_inventory_and_markers.py**
   - 依赖 step1+step2 输出
   - 构建 F0_dataset_inventory.tsv（包含 GSE239676，来自修订2的预审计结果）
   - 构建 F0_file_manifest.tsv
   - 构建 F0_metadata_field_inventory.tsv

   - 写 F0_execution_report.md
   - 最终化 analysis_log.md
   - 输出：上述全部 + gate 判断

**共享逻辑处理**：
