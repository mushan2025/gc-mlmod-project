是的，**拟时序需要多个 root 做敏感性分析**，但必须预先规定，不能跑完以后挑一个“最顺眼”的 root。否则就很像后验调参。

我建议这样定：

**F3.2 主线拟时序 root**
主线只在 `08_malignant_epithelial_MLMOD_labeled.rds` 的恶性上皮内做，root 选低MLMOD、低CNV或 normal-like marker 较高的恶性上皮状态。这样回答的是：恶性上皮内部是否存在从低MLMOD到高MLMOD的转录状态梯度。

**F3.2 敏感性 root**
可以预设 2-3 个 root：
1. 低MLMOD四分位细胞或低MLMOD cluster。
2. normal-like malignant epithelial cluster，也就是仍被判为恶性，但更接近胃上皮分化状态的cluster。
3. 另建 `epithelial_continuum_object` 后，用高置信 Normal_Gastric epithelial 作为 root，只作为敏感性分析。

判定标准也要写清：如果不同 root 下 `pseudotime` 与 `MLMOD_Score` 的相关方向一致、高MLMOD细胞集中在相近末端/分支，才可以说“支持MLMOD相关状态梯度”。如果 root 一换方向就变、分支也变，就只能说“存在状态异质性”，不能讲演化方向。

SCENIC 是做什么的：它不是普通差异分析，而是推断**转录因子调控网络**。经典 SCENIC 流程大概三步：先根据共表达推断 TF-靶基因关系，再用 motif 富集过滤出更可信的 regulon，最后用 AUCell 给每个细胞计算 regulon 活性。原始 SCENIC 发表在 Nature Methods 2017，pySCENIC 的可扩展流程发表在 Nature Protocols 2020。

它对我们有用的地方是：F3.1/F3.2告诉我们高MLMOD细胞富集什么功能、沿拟时序怎么变；SCENIC可以进一步问“哪些转录因子 regulon 可能驱动这种状态”。比如最后不是只说一堆线粒体/应激通路，而是能提出候选调控因子。

但我反对把 SCENIC 直接写成 F3 主线硬任务。它资源重、数据库依赖强，而且结果是“调控推断”，不是实验证据。更合适的设计是拆成一个 **F3补充/增强模块**，分小任务执行：

1. SCENIC可行性检查：确认 pySCENIC/SCENIC 可用、human motif database 可获得、输入细胞数是否需要抽样。
2. 输入对象锁定：优先只用恶性上皮对象，必要时按样本/MLMOD组平衡抽样。
3. GRN推断：GENIE3/GRNBoost2 生成 TF-target 候选。
4. motif过滤：RcisTarget/pySCENIC prune 成 regulon。
5. regulon活性打分：AUCell 得到每细胞 regulon AUC。
6. 高MLMOD关联：比较高/低MLMOD regulon活性，做 sample-aware 汇总，不能只做 cell-level p值。
7. 输出候选TF：只把稳定、方向一致、非样本驱动的 TF regulon 作为候选机制。

所以我的结论是：**多个 root 敏感性应该写进 F3.2 主线；SCENIC值得做，但先作为F3增强模块，不作为阻断主线的硬Gate。**

[572] Codex | 2026-06-06 23:20:30 Asia/Shanghai
查了 Monocle3 和 Slingshot 的教程/文档，我的结论是：

**实践教程不太会直接说“必须做多个 root 敏感性分析”**，但它们都强调一件事：root 应该由先验生物学知识决定，而不是算法自动决定。Monocle3 让用户指定一个或多个起点，并建议根据已知细胞状态、marker 或早期时间点选 root；Slingshot 也说如果不指定起点，算法会按规则自动选，有时甚至是 arbitrary，因此一般推荐用先验知识指定 initial cluster。

所以我们可以这样借鉴：**多个 root 敏感性不是教程里的固定模板，而是当 root 先验不够强时的严谨性补救。** 对我们这个项目很适合，因为胃癌恶性上皮并不是真正时间序列。

我建议 F3.2 写成：

1. 主 root：恶性上皮内部的低MLMOD、低CNV、normal-like marker较高的 malignant epithelial cluster。
2. 敏感性 root A：全体恶性上皮中 MLMOD_Score 最低四分位细胞对应的 principal graph node。
3. 敏感性 root B：F1/F2 注释中最接近正常胃上皮分化状态、但仍被判为恶性的 cluster。
4. 敏感性 root C：另建 `epithelial_continuum_object` 后，以高置信 Normal_Gastric epithelial 为 root，仅作敏感性，不作为主结论。
5. 可选对照：Slingshot 自动/root-free 或默认 start 结果，只用于观察拓扑是否严重依赖人工 root，不用于主解释。

判定标准也要预注册：如果不同 root 下 `pseudotime` 与 `MLMOD_Score` 的相关方向一致、高MLMOD细胞总是偏向轨迹末端或同类分支，才说“支持MLMOD相关状态梯度”；如果 root 一换方向就变，只能说“存在转录状态异质性”，不能讲进展方向。

SCENIC 可行性方面：**可以做，但不适合一上来当 F3 主线硬任务。** SCENIC/pySCENIC 是三步：GRNBoost2/GENIE3 推断 TF-靶基因共表达网络，cisTarget/motif 过滤直接靶基因，AUCell 给每个细胞打 regulon 活性分。Nature Protocols 2020 的 pySCENIC 文章说 10,000 genes × 50,000 cells 的数据集在优化流程下可小于 2 小时，但网页版 Biomni 环境、数据库下载、依赖和 120 分钟限制会让它变得不稳。

我对我们项目的预估：

- `<=10,000` 恶性上皮细胞：可行，约 30-90 分钟，适合作为首轮。
- `10,000-30,000` 细胞：中等风险，约 1-3 小时，可能接近或超过 Biomni 单次运行上限。
- `30,000-50,000` 细胞：不建议一口气跑，容易超时或内存不稳。
- `>50,000` 细胞：主流程不建议全量 GRN 推断；可以平衡抽样做 GRN，再用 AUCell 给全量细胞打 regulon 活性。

我建议把 SCENIC 拆成 F3 增强模块：

1. `F3-SCENIC-0` 可行性预检：pySCENIC/数据库/TF list/资源/小样本试跑。
2. `F3-SCENIC-1` 输入锁定：只用恶性上皮；按 `sample_id`、`group_analysis`、`MLMOD_high_label`、`epithelial_cluster_id` 平衡抽样。
3. `F3-SCENIC-2` GRN 推断：优先 GRNBoost2，固定 seed，记录 workers 和运行时间。
4. `F3-SCENIC-3` motif pruning：生成 regulon 表。
5. `F3-SCENIC-4` AUCell：对全量 06a 或 08 对象计算 regulon 活性。
6. `F3-SCENIC-5` 关联分析：sample-aware 比较高/低MLMOD regulon活性，并检查是否被样本、cluster、nCount 或细胞周期驱动。

因此我会把 **多 root 敏感性写进 F3.2 主线**；把 **SCENIC写成F3增强模块，可拆分执行，先做可行性gate，通过后再跑正式分析**。

[575] Codex | 2026-06-06 23:36:32 Asia/Shanghai
我基本同意把 SCENIC 放进 F3 主流程，但我要保留一个限制：**它可以是主流程的正式分析模块，不应成为 F3 能否成立的唯一阻断项。**

原因是 SCENIC 的生物学价值确实高。它不是普通富集分析，而是推断 TF-regulon 活性，能回答“高MLMOD状态可能由哪些转录因子调控”。这对后续 F5-F8 选核心机制基因很有用。SCENIC 原始方法发表于 [Nature Methods 2017](https://www.nature.com/articles/nmeth.4463)，pySCENIC 可扩展流程发表于 [Nature Protocols 2020](https://www.nature.com/articles/s41596-020-0336-2)，所以工具本身够经典。

但我反驳一点：**“看起来不会非常耗时”不能作为直接全量上主线的理由。** SCENIC 最不稳定的不是 AUCell 打分，而是前两步：GRN 推断和 motif pruning。它依赖 TF list、motif ranking database、基因命名、输入规模和网页环境资源。pySCENIC 文档也显示它的输入、数据库、命令行流程都有比较明确的格式要求；在 Biomni 网页环境里，失败风险主要来自依赖和数据库，而不只是 CPU 时间。

我建议这样折中，既接受你的想法，又控制风险：

**F3.3 SCENIC regulon 分析作为主流程正式模块**
放在 F3.1 功能富集和 F3.2 拟时序之后，成为 F3 的第三个主线模块，不归入补充验证。

但设一个 **F3-Gate3a 可行性预检**：
- 检查 pySCENIC 或 R-SCENIC 是否可用。
- 检查 human motif ranking database 是否可下载或已上传。
- 检查输入对象细胞数、基因数、表达矩阵格式。
- 做小规模试跑，比如 500-1000 个平衡抽样细胞。
- 估计全量或抽样正式运行时间。

通过后进入 **F3-Gate3b 正式 SCENIC**：
- 如果恶性上皮细胞数不大，直接跑全量。
- 如果细胞数较大，按 `sample_id`、`group_analysis`、`MLMOD_high_label`、`epithelial_cluster_id` 平衡抽样做 GRN。
- motif pruning 得到 regulon。
- AUCell 可以尽量回填到全量恶性上皮细胞。
- 最后做高/低MLMOD regulon 活性比较，并用 sample-aware 汇总，不能只看 cell-level p 值。

结论强度这样写：
- SCENIC 成功且结果稳定：作为高MLMOD调控机制主线证据。
- SCENIC 成功但样本/cluster驱动明显：降级为探索性候选TF。
- SCENIC 因资源或数据库失败：不阻断 F3.1/F3.2，但记录为 F3-Gate3 technical limitation，后续可本地或服务器复现。

耗时预估我会写得保守一点：
- 小规模预检：10-30 分钟。
- <=10,000 恶性上皮细胞：约 30-90 分钟，有较好可行性。
- 10,000-30,000：中等风险，可能 1-3 小时。
- >30,000：不建议全量 GRN，建议平衡抽样 GRN + 全量 AUCell。
- 真正风险点：motif 数据库下载、内存、网页单次运行上限，而不是算法理论上能不能跑。

所以我接受你的方向：**SCENIC放进F3主流程**。但我要把它写成“有可行性预检的小Gate主流程模块”，而不是一句“运行SCENIC分析”。这样既不会降低研究质量，也不会让 Biomni 因一个重工具失败把整个 F3 搞崩。

我的判断如下。

1. `adjusted_p_value < 0.05 + |log2FC| >= 0.25`
这个适合作为 F3.1 的**主线发现阈值**。因为高MLMOD是恶性上皮内部状态差异，不是两个完全不同细胞类型，logFC 不一定很大；`0.25` 不算离谱。

2. `GSEA FDR < 0.25`
适合作为 GSEA 的探索性阈值，这是经典 GSEA 习惯。但对本研究来说，不能把 `FDR < 0.25` 的通路写成强结论。
建议写成两档：`FDR < 0.25` 为 suggestive enrichment，`FDR < 0.05` 为 high-confidence enrichment。核心叙事最好来自 `FDR < 0.05` 或多个数据库方向一致。

3. GO BP + Hallmark 作为主解释数据库
这个总体适合。Hallmark 比较凝练，GO BP 比较细，二者搭配能减少 cherry-pick。
但对我们这个课题还不够，因为 MLMOD 本质上是线粒体相关死亡/损伤状态。GO/KEGG/Reactome/Hallmark 未必能很好覆盖 mitoxyperiosis 这种新概念。

4. GO `simplify(cutoff = 0.7)`
适合。GO 冗余很严重，不做去冗余会很乱。保留简化前和简化后结果即可。

5. `minGSSize = 10, maxGSSize = 500`
适合。太小的通路不稳定，太大的通路泛化严重。这个范围对 GO/KEGG/Reactome/Hallmark 都合理。

我的判断：**整体算法选择符合本研究，但当前 F3.3 仍偏“技术可运行 + 统计筛选”，需要再加一层生物学优先级规则。** 否则确实可能变成“谁 p 值好看就选谁”，而不是“谁更像高MLMOD状态的调控因子”。

**算法是否合适**
pySCENIC 适合放在 F3.3。我们只有 scRNA，没有 ATAC/ChIP，所以 SCENIC 能提供的是“TF-regulon 活性候选”，不是实验证明。它正好能回答：高MLMOD恶性上皮状态是否伴随特定转录因子调控程序增强。

GRNBoost2 作为主算法也合适，因为它比 GENIE3 更适合大单细胞数据。GENIE3可以作为小规模敏感性或 fallback，不适合默认全量跑。

**哪里可能过松**
1. preflight 里“至少20个regulons”只是技术通过标准，不能说明生物学结果可靠。正式结果还要看 regulon 数量、目标基因数、样本覆盖和稳定性。
2. “adjusted p < 0.05 或方向稳定”这句话有点松。方向稳定可以作为候选，但不能和 FDR<0.05 等价。
3. 抽样如果为了“平衡”而过度放大稀有层，可能让少数样本/cluster影响GRN。

**哪里可能过紧**
1. 基因过滤 `max(50 cells, 1%)` 对普通基因合理，但对低表达 TF 可能偏紧。很多 TF 本来表达低，过严会丢掉生物学关键因子。
2. 要求 TF 覆盖至少3个 sample_id 合理，但不能直接删除只在少数样本出现的TF，尤其PM只有3个样本。更适合标记风险，而不是硬排除。
3. sample-level FDR<0.05 可能漏掉真实但样本量不足的调控因子，所以需要 Tier 分级。

**生物学意义需要补强**
我建议候选TF不要只按统计显著性选，而是分层：

- **Tier 1 高可信候选TF**：regulon活性高低MLMOD差异 FDR<0.05；effect size明确；TF自身在恶性上皮表达；regulon target与non-scoring高MLMOD marker、MitoCarta/MitoPathways或F3.1关键通路有交集；沿pseudotime方向一致；非样本/cluster/QC驱动。
- **Tier 2 生物学候选TF**：FDR未达0.05但方向跨样本稳定，effect size明确，并且有强生物学支持。
- **Tier 3 探索性TF**：只在cell-level显著、只在单一cluster/样本显著，或target过少/过泛。

这样就不会过分迷信数学显著性，也不会放任主观挑TF。

**我建议继续修改 F3.3**
主要改四点：

1. TF过滤改为普通基因和TF分开阈值，低表达TF不直接删，标记风险。
2. 抽样改为“分层限额 + 总目标细胞数”，防止稀有层被过度放大。
3. preflight明确只是技术门槛，不代表生物学可信。
4. 增加 `F3_SCENIC_candidate_TF_biological_review.tsv`，专门记录TF表达、target功能、MitoCarta overlap、pseudotime一致性、胃癌/转移/线粒体应激相关证据和最终Tier。

所以答案是：**当前F3.3没有明显过松或过紧到不可用，但还不够生物学导向。需要把“统计显著TF”升级成“统计 + 稳定性 + 生物学机制一致”的候选TF分级体系。**
