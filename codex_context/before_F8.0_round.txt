**F7.1 问题**
1. TMB 分析写得太粗。
   TMB 不能只是“突变数”。必须规定 MAF 来源、突变类型、是否只算 nonsynonymous coding mutations、分母 Mb 如何定义。还要调整 MSI，因为 MSI-H 会强烈影响 TMB。否则核心基因高表达组 TMB 高，可能只是 MSI 混杂。

2. MSI 不能从表达矩阵随便推断。
   必须使用 TCGA 已有 MSI 状态、分子分型或可靠临床/分子注释来源。若没有可靠 MSI 字段，只能标记 not_available，不能用免疫分数或 ML 结果代替 MSI。

3. CNV 分析要分清两件事。
   一是核心基因自身 CNV 是否影响核心基因表达；二是核心基因高低表达组是否有不同 CNV 负荷/特定扩增缺失。前者比较直接，后者更容易受 subtype/purity 混杂。需要分开写。

4. “共突变基因”这个表述有风险。
   如果核心基因本身很少突变，按“核心基因突变组”分析会没有统计功效。更合理的是：核心基因高/低表达组的突变景观差异，或核心基因表达与 TP53、CDH1、KRAS、ARID1A 等关键突变状态的关联。若某核心基因突变样本数 <10 或突变率 <5%，不得做核心基因突变组主分析。

**F7.2 问题**
1. GSEA 排序规则没写。
   应预注册：按核心基因连续表达相关系数排序，或高/低表达组差异统计量排序。禁止跑多个排序方式后挑最漂亮的。还要记录 MSigDB/Reactome/KEGG/Hallmark 版本。

2. GSEA 有循环定义风险。
   如果通路富集里出现 MLMOD scoring genes、核心候选基因本身，可能只是定义变量驱动富集。必须做 sensitivity：去除核心基因和 MLMOD signature genes 后重新跑或标记 circularity warning。

3. WGCNA 不是任何样本量都能做。
   WGCNA 对样本量和表达矩阵质量要求高。需要设置最低样本数，例如 matched expression samples <50 不做主分析，<100 只能探索。还要保存 soft threshold、module eigengene、网络对象和参数。

4. 转录调控部分逻辑混在一起。
   JASPAR 启动子 motif 只能说明“潜在 TF 结合位点”，不能证明调控。TCGA 甲基化能支持“启动子甲基化与表达相关”，但不能验证 TF 结合。建议拆成两条：TF motif/TF activity 探索；DNA methylation-expression 关联分析。

5. 甲基化验证需要非常具体。
   要规定使用 450K/EPIC 哪种平台、CpG 到 promoter 的映射规则、beta 值处理、核心基因表达匹配、相关方法、多重校正。否则“TCGA甲基化验证”太空泛。

[0952] Codex | 2026-06-11 17:57:15 Asia/Shanghai
目前我挑刺主要遵循这几类原则：

1. **先问这一步是否服务核心科学问题**
   不因为“能跑”就做。每一步都要回答：它是否帮助证明或限定“胃癌 MLMOD 高活性恶性上皮亚群及核心基因的生物学/临床意义”。

2. **区分主证据、补充证据、探索性证据**
   单细胞、bulk、免疫预测、多组学、通路分析的证据强度不同。不能把探索性结果写成验证，不能把相关性写成机制，不能把预测写成临床获益。

3. **所有关键决策必须可审计**
   包括数据来源、版本、样本纳排、参数、随机种子、软件版本、输入输出文件、checksum、中间对象。Biomni 不能只口头报告，必须输出表格和 manifest。

4. **防止逻辑循环**
   例如用 MLMOD signature 定义高低组，又用同一批基因证明 MLMOD 通路富集；用核心基因参与模块评分，又说模块与核心基因相关。凡是有 overlap，都要标记并做去除重叠后的敏感性分析。

5. **防止样本独立性错误**
   单细胞不能把细胞当患者；bulk 多组学不能把同一 patient 的多个 aliquot 当独立样本；可能重叠的队列不能当独立验证。

6. **统计显著性必须配合效应量和生物学意义**
   不只看 p 值。要求效应量、FDR、多重校正范围、方向一致性、样本量、低功效警告和解释等级一起判断。

7. **关键混杂必须预先识别**
   例如肿瘤纯度、TME 组成、MSI、EBV/GS/CIN 分型、平台批次、治疗背景、样本部位。混杂不能只写 warning，要能影响最终解释等级。

8. **Gate 必须能真正阻断**
   每个 F 节都要有输入准入、审批暂停点、PASS/PASS_WITH_NOTED_LIMITATIONS/FAIL，以及失败时不得自动进入下一节的规则。

9. **Biomni 执行友好但不为简化牺牲严谨性**
   不是为了让 Biomni 好跑而选低质量方法，而是把方法、fallback、失败处理、审批点和输出字段写清楚，减少它自由发挥。

10. **上下游字段必须闭合**
   比如 F2-Gate4 解释等级要传到 F3/F4/F5/F6/F7；`allowed_for_F7` 要来自 F5；F6/F7 不能自己换核心基因。

11. **解释边界要提前写死**
   bulk 相关性不能证明恶性上皮内在机制；TIDE/IPS/SubMap 不能证明免疫治疗获益；JASPAR motif 不能证明 TF 调控；WGCNA 共表达不等于因果。

12. **优先让方案能被未来复现和审计**
   所以经常要求输出 sample-level 表、参数表、source data、RDS/中间对象、下载计划、manifest、claim control table，而不是只输出最终图。

简单说，我不是在问“这分析能不能做”，而是在问：**做出来以后，能不能支撑我们想写的那句话；如果不能，它最多允许我们写到什么程度。**

## 方案制定前的第一原则：先摸清数据再动手

**在制定任何分析方案之前，必须先对数据集做全面的预审计（data reconnaissance）。** 不要在没看过数据的情况下写死 QC 流程或方法选择。

这条原则来自一个具体教训：在之前的项目中，biomni agent 在 F1 中跳过了 doublet 检测，理由是"author data already QC'd"；但第三方审阅时也差点误判为"完全没做 doublet 检测"——实际上原始数据已包含作者计算好的 `doublet_score` 和 `predicted_doublet` 列。如果一开始就审计了数据的 metadata 结构，双方都不会犯错。

### 通用要求

**F0（数据预审计）的产出应当直接驱动后续方案的具体参数选择。**

#### 单细胞数据审计

1. **全面审计 metadata**：列出所有 obs 列名、每列的 unique values 分布、已有的 QC 列（percent.mt / doublet_score / predicted_doublet / batch 等）、已有的注释列（cell_type / subtype 等）
2. **确认数据形态**：raw counts 还是 normalized/processed？是否已经过 QC 过滤？还是包含全部 droplets？
3. **检查原作者的 QC 标准**：原论文/GEO 描述中用了什么 QC 阈值、是否做了 doublet 检测（用了什么工具）、是否做了 ambient RNA 校正、是否已经过滤低质量细胞
4. **根据审计结果决定方案**，不写死流程：
   - 原作者已做某 QC 步骤且结果可信 → 方案中只需验证 + 记录，不需要重做
   - 原作者未做或结果不可信 → 方案中必须加入该步骤
   - 原作者提供 raw counts → 需要完整 QC 流程
   - 原作者提供 processed/filtered counts → 需要评估已有 QC 的充分性，明确记录哪些步骤被省略及其理由
5. **F0 审计结论作为 F1 方案的前置输入**：F1 的 QC 方案应写成"根据 F0 审计结论决定是否需要 X"，而不是"必须做 X"或"可以跳过 Y"

#### Bulk / 临床数据审计

6. **样本量与临床信息完整度**：训练集/验证集的样本数、事件数（死亡/复发）、缺失率、临床变量覆盖度（TNM 分期、分化程度、治疗信息等），在方案制定前确认，而不是执行到预后分析才发现事件数不够
7. **验证集可用性**：GEO 验证集是否真的包含所需的临床终点和表达数据格式
8. **平台兼容性**：芯片 vs RNA-seq，基因 ID 格式（symbol / Ensembl / probe），batch 来源

#### 空间转录组数据审计（如适用）

9. **数据格式与可用性**：确认有哪些空间数据可用、与单细胞数据的匹配性（同一癌种/同一数据来源）

### 审计产出

F0 应产出一份结构化的 **数据审计报告**（TSV + 文本摘要），作为后续所有 F 节方案的前置依据。方案中的每个方法选择都应能追溯到审计报告中的具体发现。

   如果 TF 是 MLMOD signature gene、核心候选基因，或与评分定义高度重叠，应标记 circularity warning。

3. 缺少分阶段 gate。

   - F8.4 单基因高低表达 CellChat

**F8.1 表达特征问题**
1. FeaturePlot/VlnPlot 只是可视化，不是统计证据。
   必须输出样本级或 cluster-level 统计表，不能只看图。

2. 跨细胞类型比较不能用 cell-level p 值。
   应使用 sample-level pseudobulk 或至少按 sample 聚合，避免把几万个细胞当独立样本。

1. “Seurat 中把表达置零”不严谨。

4. 高低组细胞数量差异要处理。

5. F4 已经做过主 CellChat。
