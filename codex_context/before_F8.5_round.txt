[1015] Codex | 2026-06-11 20:12:45 Asia/Shanghai
F8.1、F8.2 现在方向是对的，但还不够“防误用”。我建议改，而且 F8.2 有一处我会明确反驳当前写法。

**F8.1 的问题**
1. **缺少 assay/layer 使用规则**
现在只要求记录 `assay_or_layer` 和 `expression_unit`，但没说默认用什么。Biomni 可能用 `scale.data`、integrated/Harmony corrected layer 或自己随便选。
建议明确：表达展示和统计默认使用 RNA/SCT 的 normalized expression；检测率优先用 raw counts > 0，若 raw counts 不可用则用 normalized expression > 0，并记录限制；不得用 integrated/Harmony/scale.data 做表达量统计。

2. **“pseudobulk”定义还不够清楚**
单基因 F8 不一定需要 DESeq2 这类完整差异分析。这里更准确应是 sample-level aggregation：每个样本内计算该基因的平均表达、中位表达、检出率、pseudobulk sum/mean。
建议写清：F8.1 的主证据是 sample/patient-level aggregated expression，不是把所有细胞混在一起比较。

3. **缺少最小样本/细胞门槛**
现在写“样本覆盖不足就 not_evaluable”，但没给默认规则。Biomni 会不好判断。
建议加默认门槛：用于组间统计的每组至少 3 个 sample_id；每个纳入样本在对应细胞群中至少 20 个细胞；若达不到，只能 descriptive/visualization_only。PM 因为 n=3，最高仍然 directional_only。

4. **比较范围需要预注册，避免乱做所有两两比较**
F8.1 应明确只做几类预设比较：全细胞表达定位、恶性上皮内表达、Primary_Tumor vs PM 方向性比较、必要时按恶性上皮 cluster 展示。
不要让 Biomni 自动做所有 celltype × group × cluster 的全排列比较。

5. **统计结果缺少多重校正范围和效应量解释**
现在有 adjusted_p_value，但没写 `p_adjust_scope`。
建议 `F8_expression_statistical_results.tsv` 加：`p_adjust_scope`、`effect_size_interpretation`、`statistical_evidence_tier`。否则后面不知道校正是按一个基因、多个基因、还是所有比较一起校正。

**F8.2 的问题**
1. **我反驳当前“F5筛选所用候选池 = circularity_warning”的写法**
这太宽了。所有 F8 基因本来都来自 F5 候选池，如果都标 circularity_warning，这个字段就失去意义。
更准确的区分是：
`circularity_warning`：核心基因本身进入 MLMOD 打分签名、F2高低MLMOD marker、或某个被检验 score/module 的组成基因。
`selection_bias_warning`：核心基因是因为 F2/F3/F4/F5 的某类结果被选入 F5，因此后续同源分析只能算内部一致性，不是独立验证。

2. **F6/F7 状态不能默认做 cell-level 相关**
F6 很多是 bulk 免疫浸润或样本级免疫状态，F7 很多是 bulk/multiomics 状态。不能把这些状态强行映射到每个细胞，然后和单细胞表达做 cell-level correlation。
建议明确：MLMOD_Score、F3单细胞通路分数可以做 cell-level visualization + sample-level验证；F6/F7 状态默认只能做 sample-level 或 gene-level integrated comparison。

3. **需要限制 tested state 数量，防止相关性钓鱼**
F8.2 不能把所有 F3/F6/F7 输出的通路、免疫指标、多组学指标都拿来和核心基因相关。
建议只允许进入：MLMOD_Score、MLMOD_high_label、F3中已经 gate 通过/获批的少数关键通路、F6/F7 claim table 中允许引用的状态。其他状态必须研究者批准。

4. **需要混杂控制**
核心基因与 MLMOD_Score 相关，可能只是因为 sample_id、epithelial_cluster_id、CNV_score、nCount_RNA、percent.mt、cell cycle、肿瘤来源组别驱动。
建议增加 `F8_state_association_confounding_audit.tsv`，至少检查这些变量；如果相关性在控制 sample/cluster 后消失，解释等级必须降级。

5. **高/低核心基因表达分组规则需要默认策略**
现在只说预注册阈值，没说默认是什么。
建议默认：Primary_Tumor恶性上皮内、按每个 sample 内 median split；若该基因检出率太低导致 median=0 且分组不稳定，则降级为 detected vs undetected 或 top quartile sensitivity，但必须写入 plan 并获批。

6. **F8.2 不能“验证”F5筛选来源**
如果某基因进入 F5 是因为它本来就是高MLMOD marker，那么 F8.2 再证明它和 MLMOD_high 相关只是内部一致性，不是新证据。
建议在结果表加 `same_evidence_reuse_warning`，这类结果最多作为 descriptive_consistency。

我的结论：F8.1 主要是补执行细节；F8.2 需要把“循环定义”和“选择偏倚”拆开，并严格限制相关性分析范围。这样 F8 才不会变成一堆漂亮但证据独立性很弱的相关性图。

[1023] Codex | 2026-06-11 20:22:06 Asia/Shanghai
F8.3-F8.5 需要改，尤其 F8.3 和 F8.5 还有几处会影响执行边界。

**F8.3 的问题**
1. **CellOracle 不是所有核心基因都适用**
CellOracle/GRN perturbation 更适合 TF 或有明确调控网络位置的基因。如果 F5 核心基因是受体、配体、代谢酶、结构蛋白或普通 marker，强行做 CellOracle perturbation 可能没有生物学意义。
建议加字段：`core_gene_function_class`、`tool_applicable_to_gene`、`TF_or_regulator_status`、`reason_if_not_applicable`。非 TF/非调控基因默认 `not_evaluable`，不能硬跑。

2. **缺少工具选择优先级和 fallback 边界**
现在写“CellOracle或其他GRN工具”，太开放。Biomni 可能临时换一个不合适的工具。
建议规定：优先 CellOracle 仅限 TF/GRN 适用场景；若无真实 perturbation 训练数据，不使用 scGen/CPA 这类需要扰动数据学习的模型；没有合格工具就 `not_evaluable`。

3. **缺少负对照/稳定性检查**
模型预测很容易输出看似合理的 downstream pathway。建议要求至少做一种稳健性：随机匹配表达量基因、表达量相近非候选基因、bootstrap/subsample 或不同参数下方向一致性。
否则不能区分“核心基因特异预测”还是模型背景噪声。

4. **结果表缺少模型对象和参数文件保存要求**
F8.3 如果真的跑了，应保存 GRN object、perturbation model object、输入矩阵、参数表和日志。现在只要求结果表，复现性不够。

5. **F8.3 还需要独立审批点**
`F8_in_silico_perturbation_feasibility.tsv` 输出后，应等待研究者批准是否运行扰动模型。否则 Biomni 可能 feasibility 一写完就继续跑。

**F8.4 的问题**
1. **F4 未完成时，F8 CellChat 解释等级应自动降级**
现在允许 F4 未完成时用 F1 celltype 或批准合并规则，但没说解释上限。
建议明确：若 F4 未完成或 F4 gate = FAIL，F8 CellChat 最高只能 `exploratory_communication_hypothesis`，不得作为主线通讯机制。

2. **高/低核心基因表达组的默认准入门槛不够明确**
现在有字段但没写默认阈值。建议与 F4 口径靠齐：Primary_Tumor 中 high/low source 各至少覆盖 ≥3 个 sample_id、每组总恶性上皮 source 细胞 ≥100、dominant_sample_fraction <0.8；否则不做主 CellChat。

3. **零膨胀基因的 median split 可能失效**
如果核心基因很多细胞为 0，median split 会把大量 0 分到两组或导致组别不稳定。
建议加规则：median=0 或分组不稳定时，必须降级为 detected_vs_undetected 或 top_quartile_sensitivity，并获批，不能默认 median split。

4. **F8 CellChat 需要保存对象和参数**
当前 F8.4 没有要求输出 `F8_CellChat_parameters.tsv`、`F8_CellChat_object_manifest.tsv`、CellChat RDS 对象。后续审计和本地复现会断。建议补上。

配体/受体可能是复合体，不能只看一个基因。建议增加 `ligand_subunits`、`receptor_subunits`、`complex_handling_rule`、`p_adjust_scope`。否则 CellChat 复合体轴会被简化误读。

**F8.5 的问题**
1. **输出清单漏了 `F8_object_consistency_check.tsv`**
F8.0 已经要求输出这个表，但 F8.5 最终必交付清单没收进去，这是内部不一致，必须补。

2. **F8.2 引入的降级类别和 F8.5 允许类别不一致**

建议要么加入这个类别，要么明确映射到 `exploratory_supported` 或 `visualization_only`。我更倾向新增 `confounded_or_descriptive_only`。

现在 PASS 要求“至少一个补充机制线索可审计”。但 in silico perturbation 只是模型预测，CellChat 也只是通讯假设，二者都不能真正支撑机制语言。
