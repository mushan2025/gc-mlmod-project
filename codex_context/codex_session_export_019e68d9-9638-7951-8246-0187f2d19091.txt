**1. 关于 DoubletFinder / scDblFinder**
你说得对，不能因为“新手友好”就牺牲严谨性。这里我修正表述：工具选择标准应该是 **准确性、可复现性、领域接受度、是否适合当前数据**，易用性只能排在后面。

我建议 F1 这样定：

```text
主流程：scDblFinder
验证流程：DoubletFinder
最终删除：高置信 doublet
```

理由不是“简单”，而是 scDblFinder 有正式方法论文和 benchmark 支撑，并且它结合人工 doublet、邻域信息和迭代分类器做判断；DoubletFinder 也是常用方法，但需要 pK sweep、预估 doublet rate、homotypic doublet 校正，参数主观性更强。scDblFinder 方法来源可引用 Germain et al. 2022；DoubletFinder 可作为敏感性验证。来源：[scDblFinder PubMed](https://pubmed.ncbi.nlm.nih.gov/35814628/)，[scDblFinder vignette](https://bioconductor.statistik.tu-dortmund.de/packages/3.17/bioc/vignettes/scDblFinder/inst/doc/scDblFinder.html)。

最终规则不要写成“scDblFinder 说是 doublet 就删”，而是：

```text
删除 high-confidence doublets：
1. scDblFinder 判定为 doublet；
```

**3. InferCNV 参考细胞到底用什么**
这里不能拍脑袋。InferCNV 官方说明是用一组 reference “normal cells” 来和疑似肿瘤细胞比较；运行文档也明确 `ref_group_names` 应该是非肿瘤正常细胞类型。来源：[inferCNV Bioconductor vignette](https://master.bioconductor.org/packages/release/bioc/vignettes/infercnv/inst/doc/inferCNV.html)，[inferCNV Running docs](https://github.com/broadinstitute/infercnv/wiki/Running-InferCNV)。

我建议这样定：

```text
主参考：
高置信非上皮细胞，包括 T/NK/B/myeloid/endothelial/fibroblast。
```

但这里有一个细节：不要把所有参考细胞粗暴混成一个标签，最好按细胞类型保留参考组，例如：

```text
ref_T_NK
ref_B
ref_myeloid
ref_endothelial
ref_fibroblast
```

原因是不同谱系本身表达差异很大，分组参考比混合参考更容易检查异常。

然后做两个敏感性分析：

```text
敏感性分析 A：仅用免疫细胞作为 reference。
敏感性分析 B：加入正常上皮作为 reference。
```

如果三种参考方案得到的恶性上皮结论基本一致，可信度高。
如果加入正常上皮后结果大变，要警惕癌旁上皮或正常上皮状态差异影响基线。

**4. 高置信恶性细胞很少怎么办，InferCNV 阈值怎么定**
InferCNV 没有一个通用阈值。不能写死 `CNV score > 0.05` 这种没有依据的标准。

建议用经验分布定阈值：

```text
CNV_score = 每个细胞 inferCNV 平滑表达偏离 0 的平均绝对值或均方值。
参考细胞 CNV_score 分布 = normal baseline。
阈值 = reference CNV_score 的 99% 分位数，或 median + 3*MAD。
```

最终恶性判定不要只看单细胞，要看 cluster 级别：

```text
高置信恶性 epithelial cluster：
1. epithelial marker 阳性；
2. 来自 tumor/metastasis 样本为主；

4. CopyKAT 中多数细胞为 aneuploid；

```

如果高置信恶性细胞非常少，先不要强行推进 F2。按顺序排查：

```text

2. epithelial 细胞提取是否太严格？
3. InferCNV gene_order_file 和基因名是否匹配？
4. cutoff 是否不适合当前矩阵？
5. reference 是否污染了疑似肿瘤上皮？

```

CopyKAT 论文也提醒：如果正常细胞太少，或肿瘤接近二倍体、CNV 很少，CNV 方法可能误分类。来源：[CopyKAT Nature Biotechnology 论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC8122019/)。

```text
high_confidence_malignant：InferCNV + CopyKAT 一致
probable_malignant：二者之一支持 + 肿瘤来源 + epithelial marker
uncertain_epithelial：证据不足，不进入主分析
```

**1. 恶性判定标准要写清楚**
是的，恶性上皮 cluster 里的个别细胞完全可能“不满足 inferCNV 单细胞恶性标准”。这不奇怪，因为 scRNA 推 CNV 本来有噪声、dropout、测序深度差异，而且 inferCNV 关注的是大尺度染色体片段增减，不是每个细胞都能稳定判出来。inferCNV 官方说明也是用表达强度沿染色体位置相对正常参考细胞推断大尺度 CNV，而不是提供一个天然的“恶性/非恶性”绝对标签；CopyKAT 论文也强调它是从 scRNA read depth 推断 CNV/aneuploidy 来区分癌细胞和正常细胞。来源：[inferCNV vignette](https://bioconductor.org/packages/release/bioc/vignettes/infercnv/inst/doc/inferCNV.html)，[CopyKAT Nature Biotechnology](https://www.nature.com/articles/s41587-020-00795-2)。

我建议 F1 写成分层标准：

```text
候选细胞范围：
只在 epithelial cells 中鉴定恶性细胞。
```

```text

CNV_score 高于 reference cells 阈值。
阈值 = max(reference 99%分位数, reference median + 3*MAD)。
```

```text
CopyKAT 单细胞阳性：
CopyKAT 判定为 aneuploid。
```

```text
恶性上皮 cluster：
1. epithelial marker 阳性；
```

```text
malignant_high_confidence only
```

GSE206785 外部单细胞验证是什么意思

--------------------------------------------------------------------------------

[033] Codex | 2026-05-29 19:52:55 Asia/Shanghai
“GSE206785 外部单细胞验证”的意思是：**不用它来替代 GSE183904 的主分析，而是用另一个独立胃癌单细胞数据集，检查我们在 GSE183904 里发现的结果是不是只在一个数据集里偶然出现。**

举个例子。

我们的主线是：

```text
GSE183904
正常 / 原发胃癌 / 腹膜转移
↓
鉴定恶性上皮细胞
↓
计算 MLMOD_Score
↓
找高 MLMOD 恶性上皮亚群
```

如果我们只在 GSE183904 里发现：

```text
高MLMOD恶性上皮细胞存在
高MLMOD亚群有某些marker
高MLMOD亚群富集某些通路
```

审稿人可能会问：这是不是 GSE183904 这个数据集特有的批次、样本组成、处理方式造成的？

所以我们再拿另一个胃癌单细胞数据集，比如 `GSE206785`，重复验证一些核心结论：

```text
GSE206785
独立胃癌单细胞数据
↓
同样识别上皮/恶性上皮细胞
↓
同样计算 MLMOD_Score
↓
看高MLMOD细胞是否存在
↓
看核心marker/通路是否一致
```

这就是外部单细胞验证。

但注意：它不是所有结果都能验证。比如如果 GSE206785 没有腹膜转移样本，那它就不能验证“腹膜转移中高MLMOD比例更高”这个结论。它能验证的是更通用的东西：

```text
1. MLMOD_Score在胃癌恶性上皮细胞中是否可检测。
2. 高MLMOD恶性上皮亚群是否在另一个胃癌数据集中也存在。
3. 高MLMOD亚群marker是否有部分重现。
4. 核心候选基因是否也主要表达在恶性上皮细胞。
5. 高MLMOD相关功能通路是否方向一致。
```

所以我说它是“外部单细胞验证”，不是“主分析数据”。

我的倾向是：
**F1主分析仍以 GSE183904 为核心，因为它最贴合正常/原发/腹膜转移。GSE206785 作为后续验证数据集，不要在 F1 主流程里过度混合，否则会引入新的批次和样本设计复杂度。**

**1. 能不能验证“腹膜转移中高MLMOD比例更高”？**

有可能，但要分等级。

最强验证数据应该满足：

```text
同一个独立数据集中同时有：
primary gastric cancer
peritoneal metastasis 或 malignant ascites
可用单细胞表达矩阵
最好有raw count或CellRanger矩阵
```

目前我看到比较相关的是：

```text
GSE163558
```

它是胃癌原发和多部位转移单细胞数据，GEO写明包含 primary gastric cancer、adjacent non-tumoral，以及 liver、peritoneum、ovary、lymph node 等转移样本；其中有一个 peritoneum metastasis 样本 `GSM5004187`，并且提供 `GSE163558_RAW.tar`，raw data 也在 SRA。它可以作为“腹膜转移方向”的外部验证，但问题是 **PM样本太少，只有一个明确腹膜转移样本**，所以只能算弱验证。来源：[GSE163558 GEO](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE163558)。

```text
GSE228598
```

它是胃癌患者腹膜细胞单细胞数据，样本来自 malignant ascites fluid 或 peritoneal washing，共 28 个样本，并且提供 `GSE228598_RAW.tar` 和 SRA raw data。它很适合验证“高MLMOD恶性细胞是否存在于腹膜/腹水环境中”，但因为它主要是腹膜细胞/腹水/冲洗液，不一定有 matched primary tumor，所以不一定能直接比较“原发 vs 腹膜转移比例更高”。来源：[GSE228598 GEO](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE228598)。

```text
HRA002712
```

Nature Communications 2023 那篇腹水单细胞文章，包含 35 位患者、191,987 个腹水癌细胞/免疫细胞，非常适合研究 gastric cancer peritoneal metastasis；但数据在 GSA-Human，controlled access，不一定能直接下载。来源：[Nature Communications 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC9929081/)。

所以我的判断是：

```text
主分析：GSE183904，用它回答“正常/原发/腹膜转移”。
外部弱验证1：GSE163558，用它验证原发与单个腹膜转移样本中MLMOD趋势是否一致。
外部验证2：GSE228598，用它验证高MLMOD恶性上皮细胞是否在腹膜/腹水环境中可重复出现。
可选增强：申请HRA002712，如果能拿到，用作强腹水/腹膜转移验证。
```

如果你问“有没有一个完美公开数据集能直接验证腹膜转移中高MLMOD比例更高？”
我现在不敢说有。**GSE163558能做，但PM样本少；GSE228598腹膜样本多，但缺原发对照；HRA002712强但受控访问。**

**为什么一开始注意到GSE206785？**

不是因为它能验证腹膜转移。
我注意到它有两个原因：

```text
1. 导师给的第一篇胃癌高干性文章同时用了 GSE183904 和 GSE206785。
2. GSE206785 是较大的胃癌单细胞数据：24个治疗前患者，48个肿瘤/匹配正常样本。
```

GEO页面写明 GSE206785 是 24 位 treatment-naive 胃癌患者的 tumor 和 matched normal tissue，共 48 个样本；但不是腹膜转移设计。来源：[GSE206785 GEO](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE206785)。

所以它适合验证：

```text
MLMOD高活性恶性上皮亚群是否存在于胃癌原发灶；
核心基因是否在胃癌恶性上皮细胞中表达；
高MLMOD marker/通路是否在另一个胃癌队列里重现。
```

但它不适合验证：

```text
腹膜转移中高MLMOD比例更高。
```

这一点我之前应该说得更明确。

**2. 为什么有些研究会合并几个单细胞集？我们能不能也合并？**

能合并，但不能为了“样本多”盲目合并。

别人合并多个单细胞数据集，通常是为了：

```text
增加样本数和细胞数；
提高稀有细胞群检出能力；
覆盖更多组织状态，比如正常、原发、转移；
构建更完整的细胞图谱；
降低单一数据集偶然性；
为bulk去卷积或机器学习提供更稳定参考。
```

我们也可以合并。实际上已有胃癌腹膜转移相关研究合并过 `GSE183904 + GSE163558 + GSE206785`，用于构建胃癌/转移单细胞图谱。也有 2026 年的 Communications Biology 文章用 `GSE183904 + GSE163558` 构建包含 normal、primary GC 和 GCPM 的自定义单细胞参考。来源：[ScienceDirect 摘要](https://www.sciencedirect.com/science/article/pii/S0006291X25015578)，[Communications Biology 2026](https://www.nature.com/articles/s42003-026-09906-2)。

但我建议我们的方案不要一开始就把所有数据混成一个主对象。原因是：

```text
不同数据集处理流程不同，有的只有processed matrix，有的有raw count；
不同平台、组织来源、患者状态、治疗背景会带来强批次效应；
腹水/腹膜冲洗液和实体肿瘤组织不是同一种生态位；
合并后如果看到高MLMOD比例差异，很难判断是生物学差异还是数据集差异；
inferCNV和CopyKAT对数据质量、基因覆盖、表达矩阵类型很敏感。
```

我建议采用“三层设计”：

```text
第一层：主发现队列
GSE183904单独分析，回答核心问题：正常/原发/腹膜转移中MLMOD高活性恶性上皮细胞是否增加。

第二层：独立验证队列
```

**1. 为什么 Normal_Peritoneum 不直接并入 Normal_Gastric**

`Normal_Gastric` 是胃组织正常/癌旁组织，里面会有胃上皮谱系，比如 pit mucous、chief、intestinal-like epithelial 等。GSE183904 原文也把胃上皮分成不同 epithelial sublineages，例如 `CDH1` 阳性上皮、`MUC5AC/TFF1` pit mucous、`LIPF/PGA3` chief、`REG4/TFF3` intestinal-type 等。来源：[GSE183904 原文](https://pmc.ncbi.nlm.nih.gov/articles/PMC9394383/)。

**1. 文献里常常只展示一两个代表 marker，这是正常的**
很多单细胞文章的正文或图注为了节省篇幅，只会写：

```text
T cells: CD3D/CD8A
NK cells: NKG7/KLRD1
Macrophages: CD68/CD163

```

这不是说作者只靠这两个 marker 注释，而是只展示代表性 marker。比如导师给的胃癌高干性文章就是这种写法。

**2. 我们给 Biomni 的注释表不能只停留在“代表 marker”**
正式执行时，最好每个大类细胞都有一个 marker panel，而不是单基因判断。单细胞最佳实践也强调：传统 marker 注释通常基于一个或一小组 marker，但理想上应在多个数据集/来源中验证 marker set；实际注释应结合 cluster marker、参考图谱和人工检查，而不是只看单个基因。参考：[Single-cell best practices: annotation](https://www.sc-best-practices.org/cellular_structure/annotation.html)，[10x single-cell analysis best practices](https://www.10xgenomics.com/analysis-guides/best-practices-analysis-10x-single-cell-rnaseq-data)。

一般没有固定标准，不存在“每种细胞必须 ≥5 个 marker”这种规则。更准确的原则是：

**少数高特异 marker + 阴性排除 marker + cluster DEGs + UMAP/DotPlot 共同判断。**

两三个 marker 是可以接受的，尤其是胃上皮亚型或非常经典的大类细胞。但不能只有“一个marker阳性就定类”。

**其他胃癌单细胞文献的 marker 数量大概是这样：**

| 文献/例子 | 用了多少 marker |
|---|---:|
| 高干性胃癌单细胞文献：T cells `CD3D, CD8A`；NK `NKG7, KLRD1`；macrophage `CD68, CD163`；epithelial `EPCAM, CDH1`；DC `CD1C, FCER1A, CLEC9A` | 多数 2-3 个 |
| 胃癌 CAF 文献：T cells `CD3D, CD3E`；B cells `CD79A, MS4A1`；fibroblast `COL1A2, DCN`；mast `KIT, TPSB2` | 多数 2 个 |
| 胃癌代谢单细胞文献：epithelial `EPCAM, KRT18, KRT19, MUC1, MUC5AC, KRT8`；fibroblast `DCN, COL1A2, COL1A1, LUM, COL3A1`；endothelial `VWF, RAMP2, PECAM1, PLVAP` | 4-6 个 |
| 胃癌转移相关单细胞文献：epithelial `KRT8, KRT18, EPCAM`；fibroblast `COL1A1, COL1A2, DCN, LUM`；endothelial `VWF, PECAM1` | 2-4 个 |

所以我们的表里某些细胞只有 2-3 个 marker，本身不反常。比如：

- Pit mucous epithelial：`MUC5AC, TFF1`，合理。
- Mucous neck epithelial：`MUC6, TFF2`，合理。
- Intestinal-like epithelial：`REG4, TFF3`，合理。
- Treg：`FOXP3, IL2RA`，合理，但必须先确认它属于 T cell。
- Cycling：`MKI67, TOP2A`，合理，因为它是状态，不是细胞谱系。

但我要强调一点：**2-3 个 marker 只能作为预设 panel，不等于最终注释证据足够。** Biomni 真正执行时还必须输出每个 cluster 的 `FindAllMarkers`、DotPlot、FeaturePlot，并检查阴性 marker。比如一个 cluster 表达 `EPCAM + CD3D`，即使 EPCAM 很高，也不能直接叫 epithelial，很可能是 doublet 或污染。

我建议我们采用这个标准：

- **大类细胞**：至少 2 个强阳性 marker，最好 3-5 个；必须有阴性排除 marker。
- **胃上皮亚型**：2-3 个经典 marker 可以接受，但必须建立在 epithelial 背景上。
- **免疫/基质细胞亚型**：至少 2-4 个 marker，且不能用单一 marker 判定。
- **CAF、Pericyte、DC 这类异质性强的细胞**：宁愿写成 broad label 或 uncertain，也不要硬分亚型。
- **最终论文图中**：每类细胞最好展示 2-5 个 marker；补充表可以放更多 cluster marker genes。

所以结论是：我们现在 `cell_type_marker_panel.tsv` 的 marker 数量总体是符合文献习惯的。真正要守住的是：**不要为了凑数量加入证据不硬或特异性差的 marker。少但真实，比多但虚更严谨。**

[172] Codex | 2026-05-31 14:38:39 Asia/Shanghai
Cancer Discovery 2022 有 FASTQ，不等于我们能拿到 FASTQ。原因很简单：**他们是原始测序团队，实验测序时当然产生 FASTQ；但公开到 GEO 时没有提交 FASTQ**。

GEO 页面明确写了：`Raw files were not submitted due to patient privacy concerns`，公开的是 `GSE183904_RAW.tar`，但文件类型是 CSV processed data。[GSE183904 GEO](https://www.ncbi.nlm.nih.gov/geo/query/acc.cgi?acc=GSE183904)

Cancer Discovery 2022 原文方法里写他们用 `Cellranger v3.0` 从 FASTQ 比对到 hg38，生成 feature counts，然后进入 Seurat 分析。[Cancer Discovery 2022](https://pmc.ncbi.nlm.nih.gov/articles/PMC9394383/)

所以这里要分三种情况：

1. **公开 CSV 是整数 UMI count-like 矩阵**
   这是最理想情况。虽然不能从 FASTQ/Cell Ranger 开始，但仍然可以做 Seurat 下游再分析，包括 QC、整合、聚类、marker 注释、inferCNV/CopyKAT 等。结论一般不会因为没有 FASTQ 被严重质疑，只要方法里诚实写“基于公开 processed count-like matrices”。

2. **公开 CSV 是过滤后的整数 count，但没有 raw droplets**
   仍可做主线，但有边界：不能完整复现 Cell Ranger；SoupX 这类依赖 raw droplet 背景的环境 RNA 校正会受限；doublet 只能基于 filtered cell matrix 估计。这个通常还能接受。

3. **公开 CSV 是 normalized/log-transformed expression**
   这就麻烦了，只能做 limited-use。不能严谨做：
   - raw-count 层面的 QC 和 nCount 解释；
   - SoupX/decontX 这类环境 RNA 校正；
   - scDblFinder/DoubletFinder 的高置信 doublet 删除；
   - SCTransform；
   - CopyKAT；
   - 严格 inferCNV 恶性鉴定；
   - 基于 raw count 的差异表达统计。

如果只能 limited-use，后续结论会被质疑，尤其是这三类：

- “我们重新鉴定了恶性上皮细胞”
- “腹膜转移中高 MLMOD 恶性细胞比例更高”
- “高 MLMOD 亚群是一个可靠的恶性上皮亚群”

我的建议很明确：**F0 必须先审计 CSV 是否是整数 count-like 矩阵。** 如果是，GSE183904 可以作为主线；如果不是，不能硬推主线，要么改用作者原始注释做表达层面探索，要么寻找有 count-like 矩阵的外部单细胞数据作为主线。这里不能侥幸。
